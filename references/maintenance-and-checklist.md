# Maintenance & Checklist

## 1. 修改旧 HTML 时

### 应该

- 尽量整理为一套最终 CSS
- 合并重复 media query（媒体查询）
- 删除失效旧样式
- 保留清楚注释
- class（类名）保持语义明确
- 保留原始数据完整性
- 手机 / 桌面一起回归测试

### 不应该

- 文件末尾无限追加 `v1 / v2 / v3 / v4` 修补 CSS
- 同一个 selector（选择器）被十几次 `!important` 覆盖
- 为修一个手机问题破坏桌面布局
- 没有必要时引入框架
- 通过新增装饰文案掩盖结构问题

旧文件历史补丁过多时，优先做一次干净重构。

## 2. 单文件优先

私人档案页优先：

- 单个 `.html`
- CSS 内联
- SVG 内联
- 不依赖 CDN
- 不依赖网络字体
- 不依赖外部 JS

目标是：本地可打开、GitHub Pages 可部署、iPhone 文件预览稳定、易归档。

## 3. 可访问性

至少保证：

- 正文对比度足够
- 重要信息不只靠颜色区分
- 按钮有 `aria-label`
- 输入框有清楚 label / placeholder
- 焦点状态可辨识
- 点击区稳定
- 键盘 Enter 在可用 JS 环境可以触发

## 4. 最终验收清单

- [ ] 页面第一眼干净、克制
- [ ] 不像纯黑白模板
- [ ] 不像彩色 Dashboard
- [ ] 颜色都有明确语义
- [ ] 同类信息使用同一颜色体系
- [ ] Core / Normal / Quiet 层级正确
- [ ] 主要信息字重清楚
- [ ] 旧 / 备用信息有弱化
- [ ] 卡片主体仍以白色为主
- [ ] body、Header、Section 保持中性白灰
- [ ] 同一层级没有把顶部线、edge、wash、标题、按钮全部染成同一色
- [ ] 父容器和子容器没有重复叠加同一 accent wash
- [ ] 三个以上类别没有全部使用同一种蓝色
- [ ] 远看页面不会首先被识别成“一整张蓝色页面”
- [ ] 手机 390px 无溢出
- [ ] 360–380px 仍可使用
- [ ] 长邮箱 / 卡号可换行
- [ ] iPhone 输入框不自动放大
- [ ] 核心内容不依赖 iframe / srcdoc
- [ ] 核心进入 / 切换不只依赖脆弱 JS
- [ ] 复制按钮小而淡，但可稳定点击
- [ ] 没有无意义说明文案
- [ ] 短标题 / 标签 / 副标题末尾无句号
- [ ] 要求同步时使用用户最新确认内容
- [ ] HTML 没有堆叠大量旧 CSS patch

## 5. 失败信号

出现以下任一情况时，应回退重构：

- 为了修手机端不断增加 `!important`
- 同一内容在独立页和档案馆出现两个版本
- 颜色越来越多但分类更难看懂
- 复制按钮视觉很小但真实点击失效
- 密码页桌面可用、iPhone 本地预览不可用
- Header / Hero 比正文更抢眼
- 页面所有层级都在重复同一种蓝，分类关系反而消失
- 为了“像 Apple”导致大量信息失去层级
