# Hierarchy & Color

## 1. 四层职责

- **结构 / 分组**：表达信息之间的关系
- **字重**：表达重要程度
- **阴影**：表达视觉等级
- **颜色**：表达所属类别

不要互相替代。颜色不能拯救混乱结构，阴影不能代替信息分类。

## 2. Core / Normal / Quiet

### Core

适用于真正需要优先注意的主账号、主卡、核心资产、主控制块。

```css
--shadow-core:
  0 1px 2px rgba(15,23,42,.035),
  0 14px 34px rgba(15,23,42,.075);
```

### Normal

适用于普通内容卡、普通账号、日常账户。

```css
--shadow-normal: 0 4px 14px rgba(15,23,42,.035);
```

### Quiet

适用于历史、低频备用、二类卡、冷备份。

```css
--shadow-quiet: none;
```

Quiet 不是“看不清”，而是视觉上后退。

## 3. 语义色强度

推荐：

- 实色只用于小圆点 / 极小标识
- wash（淡色底）约 `0.04–0.08` alpha
- edge（淡边框）约 `0.12–0.18` alpha
- 卡片主体保持白色

```css
--accent: #2f7de1;
--wash: rgba(47,125,225,.06);
--edge: rgba(47,125,225,.14);
```

## 3.1 防止整页同色化

语义色只做导航信号，不做整页底色。

- body、Header、Section、Card 默认中性
- 同一视觉层级只选 1–2 个载体：顶部线、圆点、tag、edge、wash、进度条中的一小部分
- 父 Section 已有顶部色线时，子 Card 保持白色；子 callout 使用 wash 时，父级保持白色
- 页面主标题默认深灰；主色不自动继承到所有标题、按钮、复选框和进度条
- 三类以上内容可以分别使用低饱和蓝、青灰绿、灰紫、暖沙金，或让次要类保持中性
- 如果去掉文字后所有模块仍像同一张蓝卡，说明分类色已经失去意义

## 4. 页面级语义

### 邮箱：平台色

```css
--c-outlook: #2f7de1;
--c-gmail: #e0554a;
--c-qq: #2fa86a;
--c-apple: #8a8f98;
--c-aliyun: #2f8fe1;
--c-sina: #e08a2f;
```

### Apple ID：地区色

同地区账号聚合，颜色只帮助地区识别，不给每个账号随机颜色。

### 银行卡：用途色

- 定存：香槟金 / 暖灰金
- 日常资金流：雾蓝 / 蓝青
- 备用：中性灰
- 小额虚拟：淡紫灰 / 青灰

禁止按银行品牌 Logo 上色。

### 消费规划：资金类别色

- 虚拟消费：灰蓝紫
- 住房：暖沙棕
- 账户用途：青灰绿
- 定存：香槟金
- 总额 / 提醒：中性深灰

## 5. 最终比例

> **70–85% 中性骨架 + 15–30% 语义色层级**

颜色越多，饱和度越低。重要信息优先通过结构、字重、阴影表达。

这里的 `15–30%` 是视觉线索权重，不等于允许 15–30% 的大面积纯色块。实际染色面积应更小。
